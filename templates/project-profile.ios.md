## Validation tiers

Use the smallest tier that proves the current change. A role change is not a reason to repeat a passing command. Every component gate records exact commands, result, duration, the number of tests executed against the number requested, the toolchain triple above, and a scoped fingerprint command formed by appending its explicit source/test/config paths after `python3 scripts/worktree-fingerprint.py --`; the phase gate uses the unscoped command. Evidence is reusable only while its scope and the toolchain triple are unchanged. Raw evidence (xcresult bundles, logs, dumps) lives under the gitignored `.evidence/phase-N/gate-X-Y/`, never in `/tmp` or a session scratchpad.

Existing projects must migrate any legacy single `Validation sequence` in `docs/project-profile.md` to these three tiers. Template sync deliberately does not overwrite that project-owned file.

**Destinations.** The commands below name the simulator by `name=`. Stage 2 of the runbook pins every destination with `,OS=[runtime]` once § Simulators records the project devices, so a new runtime's device with the same name can never become the gate device silently; until then the unpinned form is the executable fallback. `-collect-test-diagnostics never` keeps a failing test from hanging in `simctl diagnose` for ten minutes.

### Tier 1 — Targeted inner loop

Owned by Implement while coding. Run focused build/test/lint checks through XcodeBuildMCP; these are rapid feedback, not a completion gate except for an explicitly `fast`, non-runtime setup/documentation component. The executable raw fallback has no unresolved placeholders:

```bash
xcodegen generate  # only when project.yml changed
xcodebuild build -scheme __PROJECT_NAME__ -destination 'platform=iOS Simulator,name=__IOS_SIMULATOR__' -quiet
swiftlint --strict  # skip if unavailable; record the skip
```

### Tier 2 — Component gate

Run exactly once for the component's final fingerprint. Implement owns this gate in the `fast` and `review` assurance lanes. Independent Test owns it in the `test` and `full` lanes; Implement does not run it first. Review consumes unchanged-tree evidence without rerunning it. The phase-final validation component uses the `phase-gate` lane instead of Tier 2.

```bash
xcodegen generate
xcodebuild build -scheme __PROJECT_NAME__ -destination 'platform=iOS Simulator,name=__IOS_SIMULATOR__' -quiet
xcodebuild test -scheme __PROJECT_NAME__ -destination 'platform=iOS Simulator,name=__IOS_SIMULATOR__' -only-testing:__PROJECT_NAME__Tests -collect-test-diagnostics never -quiet
xcodebuild test -scheme __PROJECT_NAME__ -destination 'platform=iOS Simulator,name=__IOS_SIMULATOR__' -only-testing:__PROJECT_NAME__UITests/LaunchUITests -collect-test-diagnostics never -quiet
swiftlint --strict   # skip if unavailable; record the skip
```

Replace `LaunchUITests` with the repository's stable smoke suite if it is renamed. The smoke suite covers launch, the component's primary affected flow, and a key assertion; deeper UI flows belong to Tier 3. An `-only-testing` target that matches nothing exits green having run nothing: compare executed with requested counts.

### Tier 3 — Phase gate

Mandatory and owned by independent Test after all non-final components are committed and the `phase-gate` component has passed aggregate static Review. Run the cumulative unit, integration, and XCUITest suites plus the phase plan's named UI and critical-backend Validation Targets:

```bash
xcodegen generate
xcodebuild build -scheme __PROJECT_NAME__ -destination 'platform=iOS Simulator,name=__IOS_SIMULATOR__' -quiet
xcodebuild test -scheme __PROJECT_NAME__ -destination 'platform=iOS Simulator,name=__IOS_SIMULATOR__' -collect-test-diagnostics never -quiet
swiftlint --strict   # skip if unavailable; record the skip
```

### Risk routing and shared resources

- Assign exactly one assurance lane during handoff: `fast` (Implement gate + Implement commit), `test` (Test gate + Implement commit), `review` (Implement gate + Review commit), `full` (Test gate + Review commit), or `phase-gate` (aggregate Review + mandatory Test Phase X; Review commits).
- Test is triggered by UI/OS/external behaviour not fully proven by deterministic component tests, cross-component or persistence round trips, primary-path mocks/fakes, permissions/privacy/security, migrations or destructive state, concurrency/background execution, first use of a runtime/integration pattern, or regression-prone observable behaviour. Review is triggered by shared/core/app-entry/build/config/signing files, new or changed public API/schema/protocol/cross-component contracts, security/privacy authorization, a spec deviation or ADR, an open Technical Validation risk, an ownership exception, broad scope, or incomplete/contradictory evidence. Use `full` when both sets trigger or any critical signal appears; otherwise use `test`, `review`, or `fast`. The phase-final validation component always uses `phase-gate`.
- Code authoring is serialized by default on the phase branch, with one active component-delivery engagement at a time through its gate and commit. Parallel component authors are forbidden unless this profile is deliberately extended with a complete component-branch/worktree integration protocol (branch names, base synchronization, serialized integration order, conflict owner, and post-integration evidence rule). **The simulator lease is per boot.** Before any boot — including every `xcodebuild test`, which boots its destination, and any viewer attach — list the booted devices (`xcrun simctl list devices booted`) and poll the others to `(Shutdown)`; the maximum-booted limit in § Host capacity is a hard rule. A gate also needs a **quiet host**: detach viewers after the boot, let the post-boot daemons settle, record a host snapshot (`uptime` load average, `sysctl vm.swapusage`, `df -h /`) with the evidence, and start only below the load threshold in § Host capacity. The Lead Coordinator also serializes Git-index mutation, commits, and pushes. In solo/direct mode, the acting agent verifies exclusive simulator/index ownership and self-holds the guard.
- Once the phase/component spec is approved, agents do not pause for per-component plan approval. Pause only for a material spec change, conscious descope, new external authority, or a project-profile human gate.

## Test frameworks

- **Unit:** XCTest (`Tests/`)
- **UI / E2E harness:** XCUITest on the iOS Simulator (`UITests/`) — this is the harness the Test agent's phase-validation mode runs over the phase's user-facing flows
- **Smoke suite convention:** keep one fast XCUITest smoke plan (launch → primary flow → key assertion) under ~2 minutes; Tier 2 runs it once per component fingerprint. Deeper flow suites run at Tier 3.
- **Accessibility identifiers:** every interactive SwiftUI element gets a stable `.accessibilityIdentifier` — XCUITest and the simulator MCP tools depend on them.

## Agent tooling

- **XcodeBuildMCP** (configured in this repo's `.mcp.json` with `XCODEBUILDMCP_ENABLED_WORKFLOWS=simulator,simulator-management,ui-automation`) is the primary tool for building, running, testing, and interacting with the simulator: `tap`, `swipe`, `type_text`, `snapshot_ui`, `screenshot`, log capture. Without that variable the server loads only its default simulator workflow and has no input tools at all. Prefer its tools over raw shell `xcodebuild` for interactive develop-and-verify loops.
- **ios-simulator MCP** (also in `.mcp.json`) is a **read-only verifier**: it reads the accessibility tree. On Xcode 27 its input tools fail; never plan a UI step around it.
- **Verify every UI step from the accessibility tree within a time bound** (`snapshot_ui`, `wait_for_ui`), never from a screenshot.

## Simulators

Pinned by UDID and runtime at Stage 1c of the runbook. The canonical device is never signed in.

| Role | Name | UDID | Runtime |
|---|---|---|---|
| Canonical test device — every unit test, UI test and gate | `__IOS_SIMULATOR__` | [record] | [record] |
| [iCloud] Sync-A — evidence legs only, signed in | [record] | [record] | [record] |
| [iCloud] Sync-B — evidence legs only, signed in | [record] | [record] | [record] |

- Tests never run on a signed-in simulator: a test `ModelConfiguration` without `cloudKitDatabase: .none` attaches CloudKit mirroring on an entitled test host and writes to the development schema permanently.
- Sign-in is a named human task: the agent boots the device alone → navigates to the password field → **the owner types** → the agent verifies inside the app → the agent shuts the device down and polls to `(Shutdown)`. Agents never enter credentials.
- Proof of sign-in comes from the app's account-status API; credentials lapse silently every ~9–12 h.
- Erase only a never-signed-in device; erasing a signed-in device needs the owner's approval. Never `simctl delete unavailable` or `erase all` around a runtime change.

## Human validation channel

**TestFlight on a physical device.** At the end of each phase, after the automated phase validation passes: request approval under **Required actions (human)**, then run the Distribution command below (agent-run once approved), and list "install the TestFlight build and validate the phase's flows on device" as the remaining human task. ## Distribution

`fastlane beta` (defined in `fastlane/Fastfile`) regenerates the project, archives, exports and uploads to TestFlight. The App Store Connect API key (role **Admin**) configured in `fastlane/.env` authenticates both the upload and, through `xcargs`, `xcodebuild`'s own provisioning — no Xcode account sign-in is needed, and none is relied on. The export disables Xcode's build-number management (`manageAppVersionAndBuildNumber: false`) and the lane reads the shipped build number back from the exported `.ipa` (`CFBundleVersion`): **record that number, or the TestFlight row — never the commit count.** **Agent-run only after explicit approval at the phase gate — never unprompted; one run per approval.** The export step is the authoritative preflight (`security find-identity` is not): a failed export uploads nothing and consumes no build number, so report it as a stop and obtain fresh approval before a re-run. Processing takes ~5–30 min; the TestFlight push notification signals the build is installable. `fastlane test` is an alternative wrapper for the simulator test run.

## Git workflow contract

- `main` is protected — never commit to or merge `main` directly.
- One branch per phase: `phase-[X]`. Components are serialized and committed to the phase branch, one commit per component (`feat(phase-X): Component X.Y — [name]`).
- The phase branch merges to `main` only after `docs/phase-X-test-report.md` is PASS **and** the human has approved (merge request goes under Required actions).
- Standalone fixes outside a phase: short-lived branch + PR.
